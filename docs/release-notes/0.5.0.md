# DarkCipher ServerManagement 0.5.0 (2026-10-21)

The 0.5.0 release, built from your feedback on 0.4.0. It adds proper backup and restore with tick boxes in Data &
backups, imports from mRemoteNG / SecureCRT / Royal TS and six more connection managers, an **Identity & directory** tab
with automatic Windows Hello sign-in and single sign-on into SSH (Kerberos) and Remote Desktop, a new **AUTOMATION**
section with a full Puppet screen beside Ansible, WSL management with WSL Containers, opening hosts in VS Code and other
IDEs, Microsoft Teams sharing, Pingdom checks on the dashboard, and BeyondTrust Privileged Remote Access and Password
Safe. Every new setting can be set by Group Policy, and the security-relevant ones need administrator approval. Settings
now show which controls Group Policy locks (🔒) and which need an administrator (🛡). Drag and drop shows what you're
dragging, screens refresh as soon as data changes, and several reported bugs are fixed.
It upgrades every earlier install; the installer's version number is 0.5.0.

## New

### Backup & restore (Settings → Data & backups)
- The first card of Data & backups: **Back up now (pick what)** and **Restore or import (pick what)**, both as tick trees
  (hosts by folder, credentials, cloud API keys, notes, incidents, reports, settings), password-protected .dcxbackup
  files (PBKDF2-SHA256 600,000 rounds + AES-256-GCM), read back before they count, a snapshot before every import.
- **Scheduled backups** to a folder you choose (every 1–30 days, the newest N kept, a sync-client warning for OneDrive and
  the like), encrypted with a backup password kept only in the encrypted store, with status and failure notices.
- **Rules for administrators** (admin-protected and Group Policy): allow exports, allow imports, allow credentials / keys
  / cloud API keys in exports (off: stripped from every file, including the app's own tokens), secrets in scheduled
  backups, the shortest file password. They are enforced in the export code itself, not only on screen.

### Import from other connection managers
- **mRemoteNG** (passwords decrypted, including a custom master password, whole-file encryption and pre-1.76 files),
  **SecureCRT**, **Royal TS / TSX** (.rtsz and CSV), **MobaXterm**, **PuTTY**, **KiTTY**, **WinSCP**, **RDCMan**, **.rdp**
  files and **Devolutions RDM**. Preview with ticks under the source's folders, choose the destination folder and whether
  passwords come along (straight into the vault), duplicates skipped, a snapshot first. Settings → Data & backups, Hosts → ⋯.

### Identity & directory (Settings tab)
- **This Windows account**: who you're signed in as, the PC's join state (Active Directory, Microsoft Entra ID, hybrid,
  Entra SSO token) and your Kerberos tickets; **Bind a profile to this account**.
- **Automatic sign-in**: signed in to Windows as the account a profile is bound to → that profile opens without the
  picker, signs in with your Windows session and Windows Hello opens its store. Computer policy
  `AutoProfileForWindowsAccount`.
- **Directory connections**: every AD / LDAPS / Entra profile with View configuration, Edit and a real **Test sign-in**.
- **Single sign-on to sessions**: SSH with your Kerberos ticket (Windows OpenSSH, GSSAPI; ticket forwarding off unless an
  administrator allows it) and Remote Desktop with your Windows account — single sign-on (CredSSP), **Remote Credential
  Guard** or **Restricted Admin** — chosen per host.

### AUTOMATION: Ansible and Puppet
- A new sidebar section holds Ansible and the new **Puppet** screen: the certificate authority (list with SHA-256
  fingerprints, sign, revoke, clean), agents (dry runs with --noop by default, real runs, last-run summaries, facts,
  config, disable with a reason, enable), code (environments, Code Manager / r10k deploys, Hiera lookups with --explain,
  parser validate, puppet-lint), **PuppetDB** (nodes, failed runs, a node's facts / reports / events — queried on the
  PuppetDB host with its own certificate) and **Bolt** (commands, tasks, plans). Read-only until an administrator allows
  changes; every change asks and is audited.

### WSL (LOCAL → WSL)
- Distributions with state, version, default and disk size; terminal, files, open in an IDE, start, terminate, set
  default, convert, export, import, unregister, shut down, update, install. Each distribution's `/etc/wsl.conf`,
  `/etc/hosts` and `resolv.conf` (edited as root, backed up), its addresses and listening ports, and the global
  `.wslconfig` as a form (networking mode, memory, processors, DNS tunneling…). **WSL Containers** (wslc): containers,
  images, volumes, networks, logs, inspect, a shell, pull.

### IDE integration
- **Open in VS Code** (or Cursor, VSCodium, Windsurf, JetBrains Gateway) from Hosts, File commander and WSL, through the
  editor's own link handler. Remote-SSH uses the app's own `~/.ssh/dcx_config` (no secrets; one Include line added with
  your consent, removable); a host's key goes into ssh-agent for a limited time, never onto disk.

### Microsoft Teams, Pingdom, BeyondTrust
- **Share to Microsoft Teams**: screenshots, terminal selections and incidents to a channel or chat (Microsoft Graph, as
  you; screenshots embedded) or a Teams Workflows webhook (text). Preview of exactly what is sent; secrets masked.
- **Pingdom**: a read-only API token; pin Pingdom's uptime checks to the dashboard beside the app's own.
- **BeyondTrust**: Privileged Remote Access / Remote Support Jump Items (open in your access console, add as hosts),
  access sessions, Jumpoints and Vault names; **Password Safe** managed accounts checked out for a session — linked to a
  saved host, the password goes into that session in memory and is checked back in when the tab closes, the checkout runs
  out or the app exits.

### Settings, Group Policy and UAC
- Every control that Group Policy sets is greyed out with who set it; cards list what is "🔒 Set by your organisation"
  and what "🛡 Needs administrator approval". More settings are admin-protected: confirmations, paste protection,
  session logging, automatic snapshots, the Grafana address, backups, single sign-on, Puppet changes, IDE SSH config,
  Microsoft Teams, BeyondTrust.
- Computer-only policies (`RequireDirectorySignIn`, `AutoProfileForWindowsAccount`) are now in the ADMX templates.

## Fixed
- **Dropdowns showed type names** (e.g. `DcxManager.Sessions.TerminalProfile`): the app's dropdown template now applies
  the display name; a test checks every dropdown on every Settings tab.
- **Lists didn't show something you just added until you left and came back** (Portals, File commander's host list,
  Ansible, the Toolbox): screens now follow their data while shown; a local File commander folder follows changes on disk.
- **A disconnected Remote Desktop tab stayed bright white**: it now shows why, in the app's colours, with Reconnect.
- **Dashboard drag had no visual**: a picture of the card follows the cursor, the target is outlined, the cards slide.
- **Hosts**: hosts and whole folders can be dragged within the folder tree.
- **About** reads "ServerManagement v0.5.0".
- Saving a host in the editor no longer resets its Remote Desktop fit mode, smart-card and keyboard-hook settings.

## Security
- Backup rules are enforced below every caller (exports off, no secrets, minimum password), imports can be switched off.
- Imported files: size caps, XML without DTDs (no XXE or entity expansion), every host / port / folder / name checked.
- New network destinations appear in Privacy & network: Microsoft Graph and Teams webhooks (only when you share),
  api.pingdom.com, your BeyondTrust appliances — each off until configured.
- Secrets for the new integrations (Teams webhooks and Graph refresh token, Pingdom token, BeyondTrust API secret and
  Password Safe key) are kept in the encrypted store, never in the registry or a policy; Password Safe passwords live in
  memory for one session only.
- The penetration-test suite grew with probes for every new surface (docs/SECURITY-REPORT.md).
