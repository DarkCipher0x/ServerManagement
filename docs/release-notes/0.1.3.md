# DarkCipher ServerManagement 0.1.3 (2026-10-18)

## New: terminals survive a display crash
- **What it does:** each terminal tab draws its screen in a separate browser process (WebView2). If that process crashes or hangs, the tab now builds a new display on its own.
  - **The connection is never touched.** SSH, local shells, serial and Telnet sessions stay connected, and whatever runs on the server carries on.
  - **Your output comes back.** The most recent output (about the last 500,000 characters) is replayed.
  - **You're told.** The status line says "display restarted after: …".
- **Limit:** at most 3 restarts in 10 minutes per tab. After that the tab says so and reminds you the session is still connected, instead of looping.
- Before this release a crashed display meant "reopen this tab", which lost the session.

## New: one copy of the app at a time
- **Starting the app again** (Start menu, shortcut) now brings the running window, or its unlock screen, to the front instead of opening a second copy.
  - Two copies can no longer write the same encrypted data store at once.
- **Each data store has its own browser profile:** a test or scratch store (DCX_DATA_DIR) never shares one with your installation.
  - This removes the root cause of an old intermittent terminal-loading failure.

## Before you rely on it
- **Verified by the automated self-test** (167 checks, no failures, several runs). The tests do the real thing: they launch a real second copy of the app and kill a real terminal display process while a shell is running in it.
- **Not code-signed:** SmartScreen shows "unknown publisher", and in-app updates stay switched off.
- **Not covered yet:** web console windows and the document viewer still show a message on a display crash. Reopen them.
