# DarkCipher ServerManagement 0.1.10 (2026-10-18)

## Unraid connects when introspection is switched off
A production Unraid API refuses GraphQL schema introspection. Adding such a server under Infrastructure stopped at
"HTTP 400: GraphQL introspection is not allowed".

The app now notices that refusal and finds out what the server offers in another way:
- **Reading:** it asks for the Unraid fields it knows (server info, array and disks, Docker containers, VMs). The
  server's own error messages say which fields this API version doesn't have; the app drops those and asks again.
- **Changes:** for each container and VM action it checks that the server knows the operation, without ever running
  it. The required container or VM id is left out on purpose, so the server rejects the request before doing anything.
- The provider's notes say when this happened: *"This server has schema introspection switched off …"*.

Nothing to change on the Unraid side: you don't need to turn introspection on.

## Before you rely on it
- **Verified by the automated self-test**, including a fake server that refuses introspection (no failures; see
  TESTING.md for the count). Not yet tried against a real Unraid server.
- **Not code-signed:** SmartScreen shows "unknown publisher", and in-app updates stay switched off.
