# DarkCipher ServerManagement 0.1.17 (2026-10-19)

## New features

### Portal browser built in
- **Part of the app:** the portal browser (web UIs of routers, NAS, Proxmox, iDRAC… in tabs) no longer needs an add-on. Portals is in the sidebar under SERVERS and 🌐 Open web UI is on hosts.
- **Switch:** Settings → Integrations → Portal browser turns it off and on.
- **The add-on** still works if it is installed, and its starter bookmarks are still offered.

### Faster AI
- **Answers stream** as they are written on every engine: Foundry Local, Ollama, OpenAI-compatible servers and the Claude API.
- **The model is warmed** while you type your first character, and kept loaded only while you use the AI (10 minutes after the last use by default).
- **Connections stay open** between questions, and the fixed part of the prompt is identical every time, so local engines reuse it.
- **Independent read-only lookups** run at the same time.
- **Timings** (first text, total) are shown in the AI Engineer's STEPS and the operator's status line.
- **Measured against a fake engine:** time to the first text 692 ms → 151 ms (whole answers vs streaming; the whole answer takes about the same, 692 → 711 ms); three independent 300 ms read-only tools 1,352 ms → 743 ms; 0 new connections for 6 questions (the pooled connection is reused).

### Agents
- **The agent loop:** both AI surfaces plan, call tools, observe and continue, up to a step limit (Settings → AI speed, agents & memory).
- **Step log and Stop:** a visible step log (STEPS in the AI Engineer) and ■ Stop at any point.
- **Tool calling on every engine**, with automatic fallback for models that can't call tools.
- **Model per chat:** pick another model of the same engine for one conversation.
- **The AI Engineer** now has the operator's full set of tools (agent mode, per conversation, on by default).

### The AI Engineer commands its terminal session
- **Commands in the chosen target session:** run them and read the results; each one is reviewed.
- **Auto-run read-only commands in the target session** (off by default):
  - read-only commands run without a review;
  - changes, sensitive and destructive commands still get the review and typed confirmation;
  - never in PRODUCTION, never interactive or endless commands.
- **New abilities:** read the screen, send keys, press Ctrl+C, ask to switch the target or open a new SSH session to a saved host (only your yes changes the target). All audited.

### More AI tools
- Infrastructure actions per object (including 0.1.14's snapshots, clone, migrate and backup).
- Cloud screen actions (you approve the exact request; no deletes or consoles).
- Add to a note; open an incident or add to its timeline.
- The transfer queue and history.
- Portal bookmarks (open one for you).
- Shared libraries (hosts only, never credentials).

### Memory guard
- **Under memory pressure** (the freeze on 19 October):
  - the AI asks for a smaller context;
  - it unloads its model after the answer;
  - it unloads idle Foundry Local models.
- **It never stops** Ollama or Foundry Local.

### Add-ons: encrypted end to end
- **Encrypted bridge (API 2).** Every message between the app and an add-on program is now encrypted with AES-256-GCM. The keys are agreed fresh for every run (ECDH P-256). A message that has been changed, replayed or sent in plain text stops the run straight away.
- **Sealed add-on process.** No other program, including other add-ons, can open a running add-on to read its memory, take over its connection or inject code into it. It inherits only its own three pipe ends, never any other handle of the app.
- **Encrypted at rest.** Theme, portal browser and shared library add-ons are stored encrypted on disk under your store key and are checked every time they're read. Add-ons you already have are encrypted in place the first time 0.1.17 starts.
- **SDK.** `samples/addons/sdk` (DcxBridge.cs, DcxBridge.dll and DcxAddon.ps1) does the encryption for your own add-ons, including Windows PowerShell 5.1 scripts. The hello-hosts sample (1.1.0) uses it.
- **Updated packages** in `dist\addons\`, each with a `.sha256` and a zipped copy (`dist\addons\<id>.zip`):
  - the sample theme 1.2.0 (an organisation's branding at the time; the neutral Ocean sample since 0.4.0);
  - portal browser 1.0.1;
  - Shared library 1.0.1;
  - hello-hosts 1.1.0.

### Shared library add-on
- **`com.darkcipher.shared-library`** switches the Shared library on. The sidebar item now appears only while a library add-on is enabled, the same way Portals worked with its add-on.
- **Create a library…** still makes each team's own add-on, carrying that library's id and owner fingerprint. That is the add-on colleagues use to join.

## Behaviour changes
- **Old add-on programs stop working.** Program add-ons built for the old, unencrypted bridge (API 1) are refused at install and blocked if already installed; rebuild them with the SDK. Data-only add-ons (themes, portal browser, shared libraries) are not affected.

## Fixes
- **Terminal typing lag:**
  - **Echo:** a typed character's echo is drawn at once instead of waiting for a low-priority timer that other UI work could delay.
  - **Writes:** keystrokes are sent from a background writer, so a slow SSH connection or a busy shell can no longer stall the window.
  - **Measured** (local PowerShell, with background UI work): the echo of a typed character reached the page in 469 ms → 13 ms (median of 8) while other UI work was running.
- **AI operator:** tool lines no longer block the window while it updates them.

## Known limitations
- Streaming and tool calling follow each engine's documentation. They were tested against a local fake engine, not yet against real Ollama, Foundry Local, LM Studio or Claude API models with tools.
- The memory guard sees GPU memory only through Ollama's report and the commit charge.
