# ServerManagement 0.5.3 (2026-10-21) – DarkCipher Systems

A fix release: the real cause of the freeze 0.5.2 set out to fix.

## Fixed
- **The app stopped taking clicks after a right-click** (LOGS → Error log first; 0.5.1 and 0.5.2), and closing the window
  left it running until it was ended in Task Manager. 0.5.2's new text menus didn't cure it because the menu wasn't the
  cause. A look inside a frozen copy showed the app wasn't stuck at all: its work queue (clicks, drawing, closing the
  window) had stopped because the one message Windows' UI framework uses to wake that queue was lost while a menu was
  being laid out. A **watchdog** now sends that wake-up again: straight away when the app sees the message being lost, and
  within about two seconds whenever queued work stops running for any reason. A stall like this is written to the error
  log, so it can't go unnoticed again. The self-test reproduces the stalled state on every build and requires the app to
  recover.
- The highlight-and-copy text menus from 0.5.2 stay.

## Security
- The watchdog sends one message, the UI framework's own wake-up, to the app's own hidden window; nothing leaves the
  process and nothing is read from other programs. No change to storage, encryption, network access or policies.
