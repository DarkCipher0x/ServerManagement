# ServerManagement 0.5.5 (2026-10-21) – DarkCipher Systems

The mouse is let go after a click that closes a right-click menu.

## Fixed
- **Right-click in the log, then left-click in the log, still locked the mouse into the pane** (0.5.4 fixed the plain
  right-click). The left-click that closes the menu goes down on the log, which takes the mouse to select text, but
  comes up on the menu as it closes, so the log never learnt the button was released and kept the mouse. 0.5.4's guard
  asked the UI framework whether a button was pressed, and it wrongly said yes. 0.5.5 asks Windows for the physical
  button state instead, so the mouse is released as soon as you move it with no button held. Real drags (selecting text,
  resizing, moving tabs) are unaffected because a button is down throughout. The self-test checks both cases.

## Security
- No change to storage, encryption, network access or policies.
