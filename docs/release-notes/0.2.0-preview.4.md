# DarkCipher ServerManagement 0.2.0-preview.4 (2026-10-20)

Everything in preview.3, plus Microsoft Azure and Google Cloud, and the app rebuilt as separate projects. The installer
version is 0.1.24, so it upgrades preview.3 and the final 0.2.0 will upgrade it.

## New

### Microsoft Azure
- **Settings → Cloud providers → Azure subscriptions → ＋ Add subscription.** The app signs in as an Entra app
  registration with a **certificate** (a .pfx with its private key; client secrets aren't accepted). You give it the
  tenant id, the application (client) id, the subscription id and the .pfx; it signs in once to check before saving.
  The certificate is kept only in the encrypted settings.
- **Read-only until you allow it.** A new subscription only reads; "Allow changes / read-only" switches it, and every
  change still asks first. Azure itself still checks the registration's role.
- **Screens:** virtual machines (start, stop = deallocate so billing stops, power off — still billed, restart,
  redeploy, resize, instance view), AKS clusters (start / stop) and node pools, App Service (start / stop / restart),
  Azure SQL servers and databases, disks (snapshot) and snapshots, storage accounts, virtual networks, network security
  groups and their rules, public IPs, load balancers, DNS zones and records, key vaults (settings only), resource groups,
  every resource, locations, and a read-only API explorer.
- Changes in Azure take a while: the app follows each one until Azure says it finished, or shows why it failed.

### Google Cloud
- **Settings → Cloud providers → Google Cloud projects → ＋ Add project.** The app signs in as a **service account**
  with its JSON key file. Key files that point anywhere but Google's own sign-in are refused. Delete the downloaded key
  file afterwards; the app keeps its own encrypted copy.
- **Read-only until you allow it** — and while a project is read-only the app asks Google for read-only access too.
- **Screens:** VM instances in every zone (start, stop, hard reset, suspend / resume, machine type, serial output),
  custom images, disks (snapshot) and snapshots, GKE clusters and node pools (set size), Cloud Run services and
  revisions, Cloud SQL instances (start / stop / restart), databases and backups, Cloud Storage buckets (settings),
  VPC networks, subnets, firewall rules, IP addresses, load balancer front ends, Cloud DNS zones and records, regions,
  and a read-only API explorer.

### Both clouds
- They sit in the Cloud providers workspace next to Vultr, Contabo and Hetzner, on the dashboard, in Privacy & network
  (every host they talk to), in offline mode (blocked like the others) and in backups.
- **Never read:** keys, secrets, connection strings, publishing credentials, Cloud SQL users, object contents.
- The AI tools (cloud lists, instance power, screen actions) work with both, with the same approvals.

### Under the hood
- The app is now ten projects with dependencies pointing one way only (checked by the self-test), and the biggest
  files are split up. With AI features off, the AI part of the app is never loaded.
- The PDF guide's user chapter comes from the help file again (it had moved with the split).

## Not tested on real accounts yet
Azure and Google Cloud were tested against simulated sign-in and API servers only. Please try a subscription and a
project (read-only first) and tell me what you see.

## Known gaps
- No serial console on either cloud (Google VMs offer the read-only serial output instead).
- Azure VM rows show no IP address (Azure keeps addresses on the network interfaces); SSH and "add to hosts" ask for it.
