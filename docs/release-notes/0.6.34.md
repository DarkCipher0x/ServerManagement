## OpenAI API
A new AI engine for OpenAI's own GPT models (Settings → AI engine → **OpenAI API**), alongside the generic
OpenAI-compatible engine that stays for LM Studio, vLLM, Azure OpenAI and gateways (ADR-111).
- **The Responses API.** Current GPT models call tools only through OpenAI's Responses API, so the engine speaks it:
  the AI Engineer's tools, streamed answers, structured results and screenshots all work, with GPT-6 Sol by default.
- **Your key, stored encrypted.** Paste a key from platform.openai.com; it is kept in the encrypted settings, never in
  the registry or an export without secrets. **Load models** lists only the models that chat.
- **Reasoning effort** (model default, low, medium, high) trades speed and cost against thoroughness.
- **Private by default.** It is an internet provider, so it is refused until you tick *Allow internet AI providers*;
  secrets are masked before anything is sent, and requests go with storage off, so OpenAI keeps no copy for later
  retrieval. Screenshots go only to models that read images.
- Group Policy can set the address, model and reasoning effort (not the key).

## Portals in the hosts panel
Right-click a portal tab (or use its ⋯ menu, or the Portals screen) → **📌 Pin to the hosts panel**. Pinned portals are
listed under **🌐 Portals** below Favourites in the hosts panel beside the tabs: double-click to open, right-click to open
in a window, edit, copy the address or unpin.

## Portal tabs: pop-ups blocked, sound you can mute
- **Pop-ups are blocked by default.** A window a page tries to open is refused before any browser view is made for it
  (lightweight, and nothing of it runs). **⛔ ⧉** in the tab's toolbar lists what was blocked: open one once in a tab
  (through the same address and certificate rules as any page, without a link back to the opener) or **Always allow
  pop-ups on** that site. The choice is per site (scheme, host and port), kept in your encrypted store, listed on the
  Portals screen, and audited. Group Policy can turn the blocking off for an organisation.
- **Mute a tab or a whole site.** A tab playing audio shows 🔊 in its title; click the speaker or right-click the tab →
  Portal → 🔇 Mute this tab, or **Always mute** the site so all its tabs start muted.

## Everything the app writes is encrypted
The app's own store has been sealed with its key since 0.3.0. Some files have to be read by other programs, which
don't hold that key: the portal browser's profile and cache (cookies, site storage, cached pages, crash dumps), the
Bitwarden CLI's data, a key handed to OpenSSH for an external terminal, .rdp files, files for the Share sheet or
"Open externally", SCP transfer buffers, and the default screenshot and Claude Code workspace folders.
- **Their folders are now encrypted by Windows (EFS) for your account** before anything is written to them:
  transparent to the programs that run as you, unreadable to other accounts, to the disk taken out of the PC and to
  a copy of the raw files. Files an earlier version left there are encrypted at the first start (in the background;
  the browser profile before the browser starts, at every start: the browser moves a few public files of its own
  — certificate revocation lists and the like — into its profile while it runs, and they are encrypted then).
- **Settings → Security → Verify encryption checks them too,** file by file. On Windows Home (no EFS) or a drive
  without it they stay readable only by your account, and the check says so.

## Server BMCs, HPE GreenLake and Sophos Central
Three new Infrastructure providers, each in its own small file and described by the same short record, so the add
form, its checks and the filter come from the provider itself. **＋ Add ▾** is now grouped (Containers, Hypervisors,
Storage & lifecycle, Network, Server hardware), with Sophos Central and DCX-CTL at the top level.
- **Server BMC — Redfish** (HPE iLO, Supermicro, Dell iDRAC, Lenovo XClarity Controller): systems, drive wear, power
  supplies, fans, temperatures, power draw, firmware and the BMC's event log. With "Allow changes": the power actions
  the system lists (each verified by re-reading the power state), the identify light, and restarting the BMC. https
  only with the certificate pinned; one Redfish session per refresh or action, deleted afterwards; only /redfish/v1
  addresses on the same BMC are followed.
- **HPE GreenLake:** the workspace's devices, subscriptions (expiring within 30 days flagged), the audit log and
  Compute Ops Management servers. Read-only; right-click a server → **Add its iLO as a Redfish provider** to manage it.
- **Sophos Central:** firewalls (connection, firmware, group, cluster) and firewall groups, protected computers and
  servers (health, tamper protection, isolation) and alerts, for one tenant or every tenant of a partner or
  organization account. With "Allow changes": firmware upgrade check and upgrade (only to an offered version), scan,
  update check, isolate / release (verified), acknowledge an alert.
- GreenLake and Sophos sign in with OAuth client credentials kept in the vault; the access token lives in memory only
  and goes only to the service's own https addresses (an address an answer names outside them is refused).

## Faster start, lighter process
(0.6.32 and 0.6.33 were built but never published; their work ships in this release.)
A start-up pass with a new built-in timeline (ADR-110). On the same PC, process start to the first frame of the main
window went from about 800 ms to about 650 ms with AI features off, and from about 1,170 ms to about 680 ms with
them on; the window is idle about 100 ms later.
- **Compiled ahead of time.** The app's own code and the libraries a session uses ship compiled (ReadyToRun), so a
  start no longer compiles them. The installer grows by about 7 MB for it.
- **The encrypted store opens in parallel.** The data key is unwrapped on a worker thread while the window's theme and
  fonts are set up, and the JSON metadata for your settings and data is built ahead of time, so the start-up check
  of every store file no longer waits for it.
- **Nothing loads before it's needed.** WinForms (only the embedded Remote Desktop control and the tray balloon use
  it), the AI sidebar's HTTP client and the Foundry Local check used to load or run before the first frame; they
  don't now. Three terminal filters that compiled their patterns at start-up are built at compile time instead,
  and so are those of the first terminal tab.
- **Old terminal pages are cleared.** Every version unpacks its terminal page into the cache; the folders of earlier
  versions are removed at the first start.
- **For developers:** `DCX_STARTUP_TRACE=<file>` writes the start-up timeline (each phase's time, memory and the
  assemblies it loaded); `DCX_STARTUP_TRACE_STACKS=1` adds the call stack behind every assembly load. See
  docs/BUILD.md.
