# DarkCipher ServerManagement 0.1.12 (2026-10-19)

## New features

### Theme add-ons, and the sample theme
An add-on can now be a **theme**: it replaces the app's colours (and optionally its UI font) and runs nothing.

**Install the sample theme:**
1. Sidebar → SYSTEM → **Add-ons** → **＋ Install add-on…**
2. Pick the theme's `.dcxaddon` (in this release's folder; or pack it yourself with `samples\addons\pack.ps1 samples\addons\sample-theme`).
3. The approval screen says **"This is a theme"**: no program, no permissions. Click **Install**. The app is repainted straight away.

**What it looks like:** a navy header, orange buttons and accents, white pages with light grey panels in light mode, and a deep navy dark mode (the colours of the sample organisation's public stylesheet at the time; 0.4.0 replaced them with the neutral "Ocean" sample). The header's theme selector (System / Dark / Light) still switches mode.

**Font:** the theme names Roboto. The app uses it only when Roboto is installed on the PC and you haven't picked your own UI font (Settings → Typography). Otherwise the app's own font stays. The Add-ons screen says which applies.

**Back to the default:** Add-ons → select the theme → **Back to the default theme**. **Disable** and **Remove** do the same. **Use this theme** turns it back on.

**Unofficial:** the theme held colour values only. It contained no logo, images or other assets.

## User-interface changes
- **Add-ons screen:** a theme add-on shows a THEME section: whether it is in use, the switch, colour swatches, and the font status. It shows no permissions, commands or run log, because it has none.

## Security changes
- **Themes are data, never code.** A theme-only add-on can't declare a program, commands or permissions.
- **Strict theme files:** only `#RRGGBB` colours for known keys and a font name are accepted. Unknown fields, other formats and wrong types are refused when the package is inspected, before anything is installed.
- **Environment colours stay fixed:** a theme can't recolour the PRODUCTION / TEST / LAB / DEV / LOCAL labels (ADR-017).
- **Tamper check:** the theme's files are hash-checked every time it is applied. A changed theme is not applied, the add-on is disabled with the reason, and the default palette stays.
- Switching theme is recorded in the audit log.

## Also in this build
- **Microsoft Store packaging prepared (ADR-029), not submitted.** When the app runs as a Store package, the in-app updater stays off and restarts go through the package. The website MSI is unchanged.

## Migration
- A new setting records which theme is in use (empty = the app's own theme). Nothing else changes.

## Known limitations
- A theme changes the app's colours, not shapes: buttons keep their corners, and there are no pill buttons as on the website.
- Terminal colours come from terminal profiles, and remote desktops are drawn by Windows; themes don't change either.
- Font files in a package are not loaded. Install the font in Windows to use it.
- **Not code-signed:** SmartScreen shows "unknown publisher", and in-app updates stay switched off.
