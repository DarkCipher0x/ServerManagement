# DarkCipher ServerManagement 0.1.18 (2026-10-19)

## Improvements

### The AI Engineer in PowerShell terminals
- **Readable commands:** what the AI Engineer types into a PowerShell session is now short. The first command in a session sets up a small helper (`__dcx`); after that each command shows as `. __dcx <id> '<the command>'` instead of a long encoded wrapper.
- **Your session keeps its state:** variables an AI command sets stay in your session, as if you had typed it.
- **Self-repair:** if the helper is gone (removed, or a nested shell), the app types it again by itself.

### Better risk labels
- **Reading cmdlets:** `Get-WmiObject`, `Get-Member` and other reading cmdlets (`Get-NetAdapter`, `Get-ScheduledTask`, `Get-LocalUser`, `Get-FileHash`, `Group-Object`, `ConvertTo-Json` …) are read-only. They no longer show "CHANGES the system".
- **Nested PowerShell:** `powershell -Command "…"` and `pwsh -c "…"` are judged by the command inside them. `-EncodedCommand`, `-ExecutionPolicy` and `-File` still count as changes.
- **Method calls** on objects, such as `(Get-WmiObject …).Delete()`, count as changes.
- **Fewer bad commands:** in a PowerShell session the AI is told to type cmdlets directly, never wrapped in `powershell -Command`, and to check property names with `Get-Member` first.

### Add-ons can reach everything (full-control API)
- **Everything the app can do:** an add-on can now list and call it, including:
  - status, logs, services and files on saved hosts;
  - SSH commands and transfers;
  - cloud and infrastructure actions;
  - terminal sessions, notes, incidents, portals and shared libraries.
  - Anything added to the app later becomes reachable as well.
- **New abilities:** add-ons can also add, change and remove saved hosts, and open screens and hosts.
- **Same safeguards as the AI:**
  - reads need the new "app.read" permission;
  - every change needs "app.control" and your approval of the exact action (PRODUCTION asks for the name);
  - every call is in the audit log under the add-on's name.
- **Encrypted only:** all of it goes over the encrypted add-on bridge (API 2). Every add-on must now be built for API 2 to install, themes and other data-only add-ons too. Ones already installed keep working.
- **SDK:** `Get-DcxCapabilities` and `Invoke-DcxTool` in `DcxAddon.ps1`. The sample add-on (hello-hosts 1.2.0) shows what an add-on can call.

### Build hygiene (supply chain)
- **Locked packages:** every package, including indirect ones, is pinned by version and content hash in `packages.lock.json`. The release build refuses any package that differs.
- **Vulnerability gate:** packages are checked against NuGet's advisory database on every build. A high or critical advisory stops the build. There were none at release.
- **Deterministic builds:** the same source gives the same binary.
