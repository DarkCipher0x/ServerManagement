# ServerManagement 0.6.16 (2026-10-24) – DarkCipher Systems

*Built for the launch but never published: 0.6.22 is the public beta release (it adds Bitwarden and Password Safe credentials everywhere, AI server deploys on Vultr, a better default AI model per PC and an AI Engineer fix).*

**Public beta.** Built by an IT engineer, for engineers. Free and open source (MIT). Post-quantum ready.

## A note from the developer
ServerManagement is one of my favourite projects yet, and I'm excited to finally share it. I'm an IT infrastructure
engineer, and I designed it around the job: one encrypted workstation for your servers, network, hypervisors and
clouds, without licences or per-seat pricing. This is just the start. I'll keep adding as many systems as I can, and

## Beta: please read
- **This is a beta.** Expect rough edges, and keep backups of anything important (Settings → Data & backups).
- **The installer and the app aren't code-signed yet.** Windows SmartScreen may say "Windows protected your PC": choose
  **More info → Run anyway** only if the SHA-256 of your download matches the one published with the release. The
  update information inside the app *is* signed, twice (ECDSA P-256 and post-quantum ML-DSA-65), and the app refuses an
  update unless both signatures match.
- **Testers are very welcome.** Many integrations are built against the vendors' published APIs but haven't yet been run
  against a live account, because I don't have access to those services. If you use any of them, I'd love to hear
  whether it works:
  - Microsoft 365 admin (Intune, Defender, Entra), Windows 365 Cloud PCs and Microsoft Teams;
  - Bitwarden (Password Manager and Secrets Manager, cloud and self-hosted / Vaultwarden);
  - UniFi (Network on a console or through the Cloud Connector, and Site Manager);
  - BeyondTrust Privileged Remote Access, Pingdom, Grafana / SIEM links, Elasticsearch and Loki log sinks;
  - Contabo, Hetzner Cloud, Azure and Google Cloud;
  - VMware vCenter, Hyper-V, Proxmox, Unraid, Docker, Puppet, WSL and serial consoles.
- **Bugs and feature requests:** please use the forms on darkciphersystems.com (Report a bug, and Feature requests →
  ServerManagement).

## New
- **UniFi.** Manage your UniFi network with Ubiquiti's own API keys, from Infrastructure → ＋ Add:
  - **UniFi Network**, on the console's address (UDM, UCG, Cloud Key or a self-hosted Network server) or from anywhere
    through Ubiquiti's **Cloud Connector**: sites, devices (state, firmware updates, uptime, CPU and memory, ports, PoE,
    uplinks), devices waiting for adoption, clients, networks and VLANs, WiFi, WANs, VPN servers and site-to-site tunnels,
    firewall zones and policies, ACL rules, DNS policies, guest vouchers, LAGs and switch stacks.
  - **Changes** (read-only until you turn on "Allow changes", each one checked after it's done): restart a device, PoE
    power-cycle a port, adopt or remove a device, authorise or revoke a guest, generate and delete vouchers, and switch
    WiFi, networks and your own firewall policies on or off.
  - **UniFi Site Manager** (api.ui.com): every console, site and device your account has, with health counts, firmware
    status and ISP metrics (latency, packet loss, throughput). Right-click a console to manage it through the Cloud
    Connector in one step.
- **A tidier sidebar.** New **TOOLS** (File commander, Snippets & multi-run, Tunnels, LAN discovery, Network & mail
  toolbox) and **DOCUMENTS** (Notes, Docs, Incidents, Reports) sections; Bitwarden sits under VAULT and Help under
  SYSTEM. Your own order and hidden pages are kept.
- **Bitwarden.** Sign hosts in straight from your **Bitwarden vault** (a login or an SSH key) or from **Secrets Manager**
  (service-account secrets). Link an item to a host once (right-click the host → 🔑 Sign in with Bitwarden…) and every
  connection reads its password or key into memory for that session; nothing is saved in ServerManagement. SERVERS →
  Bitwarden lists your logins, SSH keys and secrets by name, and can copy one briefly (cleared after 30 seconds and kept
  out of Windows clipboard history). Works with bitwarden.com, bitwarden.eu, self-hosted Bitwarden and Vaultwarden
  (vault only). It uses Bitwarden's own CLIs (`winget install Bitwarden.CLI`), signs in with your personal API key and
  asks for your master password when the vault is locked; the vault locks again after 30 minutes unused, with the app and
  at exit. Settings → Integrations → Bitwarden, with Group Policy for every setting.
- **Post-quantum security.** Protection against "harvest now, decrypt later": data recorded or copied today can't be
  opened by a quantum computer later. Everything uses hybrids, so it's at least as strong as before even if one half
  were ever broken:
  - **Everything saved** stays AES-256-GCM, which quantum computers don't break. The data key's protectors are
    quantum-safe too: your Windows account (DPAPI) and the master password were already; **Windows Hello sign-in** now
    combines the Hello signature with a secret only your Windows account can open. It's still one Hello prompt, and an
    existing Hello setup upgrades itself at your next Hello unlock.
  - **SSH** offers the hybrid post-quantum key exchanges first (`mlkem768x25519-sha256`, OpenSSH 10's default, and
    `sntrup761x25519-sha512`); every session's strip says what was negotiated. "Require post-quantum key exchange for
    SSH" (Settings → Security & encryption, admin-protected, Group Policy `PqSshRequired`) refuses servers without it.
  - **Shared libraries** (team sharing): new libraries and members use hybrid keys, P-256 + ML-KEM-768 to share keys and
    P-256 + ML-DSA-65 to sign, and a downgrade to classical-only is refused. Members who joined earlier keep working.
  - **Updates** are signed twice, ECDSA P-256 and ML-DSA-65, and offered only when both verify.
  - Settings → Security & encryption → **Post-quantum** shows a live check of the algorithms and what is and isn't
    covered. HTTPS to cloud and Microsoft services, Remote Desktop and SSH host / user keys use the vendors' own
    cryptography, outside the app's control; they're listed there, not claimed.
- **Docs: a Markdown editor**, separate from Notes. Runbooks and references in folders and subfolders, **pinned to
  hosts, host folders and infrastructure** (Proxmox clusters, vCenter, Hyper-V, Docker hosts…): right-click a host or a
  provider → 📄 Docs. A live preview beside the editor (or edit / preview only), a formatting toolbar and shortcuts
  (Ctrl+B / I / K / S), lists that continue themselves, Ctrl+Enter ticks a task, an outline to jump between headings,
  revisions, trash, and Markdown import / export. Every document is its own encrypted file, included in backups with
  your notes. Safe preview: only https and mailto links work (after asking), images are never downloaded, and HTML is
  shown as text.
- **Theme packs.** Settings → Appearance → Theme now offers seven built-in packs as preview tiles, each showing its dark
  and light look. **DarkCipher stays the default.** Alongside the DarkCipher packs (DarkCipher, Graphite, Teal, High
  Contrast) there are three everyday ones with their own dark **and** light palettes:
  - **Neutral**: plain greys and a blue accent, like Windows 11.
  - **Slate**: cool blue-grey with an indigo accent.
  - **Arctic**: soft polar greys and frost blue (Nord-style).

  The Mode setting (Follow Windows / Dark / Light) picks the palette. Choosing a pack also brings its own accent, unless
  you picked a different accent yourself. Environment labels (PRODUCTION, TEST, …) look the same under every pack.

## Fixed
- **The AI Engineer runs tool calls however a small model closes them.** phi-4-mini sometimes ends a call with `}}>`
  instead of `</tool_call>`; nothing ran, even after the AI Engineer asked it to try again. Any closing now counts.
- **Bitwarden tells you what's missing.** Without Bitwarden's command-line tool installed, Unlock asked for your master
  password and then failed without saying why. VAULT → Bitwarden now opens with a set-up checklist and an **Install
  Bitwarden CLI** button (it installs `bw.exe` for you with winget; the Bitwarden desktop app doesn't include it), and
  Unlock checks the CLI and your API key before it asks for the master password.
- **The AI Engineer now runs the commands small models write as text.** Small models (phi-4-mini on Foundry Local, for
  one) sometimes write a tool call out as text instead of making it, so nothing reached the terminal and made-up lines
  read like results. Those calls now run, with the same approvals and read-only auto-run rules as always. When a model
  writes a call into a sentence and then asks you to approve something that was never sent, the AI Engineer tells it
  nothing ran and switches that task to a strict tool-call format small models follow far more reliably. After two tries
  without a call, STEPS says plainly that nothing ran. Larger models (e.g. qwen2.5 7B or llama3.1 8B in Ollama) call
  tools natively and are the most reliable choice for agent mode.
- **Typing the server's name to approve now works with Enter.** On a PRODUCTION host the review asks you to type the
  host's name; Enter after typing it used to hit the default button, Cancel, so the command was reported as declined.
  Now Enter confirms once the name matches (and does nothing until it does), letter case and surrounding spaces don't
  matter, and the box says when it matches. This applies to every typed confirmation in the app.
- **The AI Engineer's target terminal defaults to the terminal you're working in.** It follows the terminal in front as
  you switch tabs, until you pick one yourself (or "none"); "↻ Follow the terminal in front" turns that back on. While
  the AI is working on a task its target stays put, so every step goes to the same session.

## Security
- **UniFi (ADR-094):** https only; the API key travels only in its header; a console's self-signed certificate is pinned on
  first use and a changed one is refused; ids from the console are checked before they're used; answers are parsed
  strictly. Site Manager is read-only.
- **Pre-launch sweep:** 16 new attack probes (193 in all, every one stopped) and 8 new fuzzed parsers (39 in all) over
  Bitwarden, UniFi and the AI tool-call reader; four robustness findings fixed (malformed answers that would have stopped
  a UniFi or Bitwarden screen instead of being refused); no known-vulnerable dependency. Details in the security report §4d.
- **Bitwarden (ADR-093):** only a CLI signed by Bitwarden (or a build an administrator approved by its SHA-256) is ever
  started, and it's checked again whenever the file changes. Your master password, API key, session key and access token
  reach it only as environment variables of that one process, never on a command line. Lists never hold a password, key
  or secret value; one is read only when a session or a copy needs it. Your master password is never stored. Switching
  the integration on, the server, using items for sessions, copying and CLI approvals all need admin approval.
- **.NET 10 (ADR-092):** the runtime keeps getting Microsoft's security fixes for years instead of weeks. Certificates
  are now loaded through .NET's stricter `X509CertificateLoader`.
- **Post-quantum (ADR-090):** ML-KEM-768 (FIPS 203) and ML-DSA-65 (FIPS 204) from BouncyCastle 2.7.0, the version SSH.NET
  already uses, so no new dependency. Every use is a hybrid with the classical P-256 key it had, and hybrid keys refuse
  classical-only signatures and wraps (no silent downgrade). The update manifest's second signature uses a new
  ML-DSA-65 release key, pinned in the app; the ECDSA release key is unchanged. The Windows Hello wrap now needs the
  Hello signature and a DPAPI-protected secret of your Windows account.
- **Not changed, by design:** the add-on bridge is a local pipe on your own PC, so recording it means already being on
  the PC; post-quantum would protect nothing there. SSH host and user keys stay classical signatures (OpenSSH has no
  post-quantum signature yet).
- **Docs (ADR-091):** documents are sealed like every other file (AES-256-GCM, bound to their file name). The preview
  never fetches anything, runs no HTML, and opens links only after asking (offline mode is respected).
- The AI Engineer fixes keep every approval. Typed confirmations are still required wherever they were; only Enter and
  letter case changed. The default target is only ever the terminal you bring to the front and never changes during an
  AI run; PRODUCTION targets still review every command.
- Every theme pack meets the house theme's contrast rules in both modes. New Group Policy values: `ThemePreset`
  (neutral, slate, arctic) and `PqSshRequired`.
