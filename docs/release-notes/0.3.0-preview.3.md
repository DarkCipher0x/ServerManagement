# DarkCipher ServerManagement 0.3.0-preview.3 (2026-10-20)

A fix preview: the AI Engineer works with the target terminal again on small local models. It upgrades
0.3.0-preview.2; the installer's version number is 0.2.5.

## Fixed
- **The AI didn't run commands in the target terminal** with some local models (seen with phi-4-mini on Foundry Local):
  the model wrote the call as text — `terminal_run(target=…, "df -h")` — instead of calling the tool, so nothing ran
  and the reply just showed the call. Such replies are now recognised and run as the tool call they describe, through
  the same approvals as always (auto-run still covers read-only commands only; everything else asks). The step log says
  when it happened. Only a reply that is nothing but calls to the offered tools counts: a command the AI merely mentions
  while explaining something never runs.

## Improved
- **Complicated scripts reach the terminal intact.** Multi-line scripts with heredocs, brackets, commas and quotes,
  triple-quoted and raw strings, and backslashes (`\.`, `\$`, `\d`) arrive exactly as the AI wrote them. On bash / sh
  targets a script containing Tabs, `!`, CR characters or non-ASCII text (or a long one) is sent Base64-encoded and run
  in the same shell, so tab completion and history expansion can't mangle it and `cd` and variables still carry over.
  Simple commands are still typed readably.

## Under the hood
- Tested with the exact reply from the bug, a set of complicated scripts, and a real bash run (Git Bash, history
  expansion on) of a heredoc with Tabs, `!`, quotes and non-ASCII text.
