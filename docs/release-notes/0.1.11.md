# DarkCipher ServerManagement 0.1.11 (2026-10-19)

## New features

### Hetzner Cloud
Add a project under **Settings → Cloud providers → Hetzner Cloud projects** with its API token (Hetzner Console → project → Security → API tokens). The token is tested before it is saved and stored only in the encrypted settings.

**What you can manage:**
- **Servers:** create, rename, labels, delete (you type the name), power on, shut down, reboot, power off, hard reset, rescue mode, rebuild, change type (resize), snapshots and backups, ISO attach/detach, private networks, placement groups, reverse DNS, protection, and root password reset. The new password is shown once and never stored.
- **Images:** system images, app images, snapshots and backups (convert, protect, delete).
- **Storage:** volumes (create, attach, detach, resize, protect).
- **Networking:** networks with subnets and routes, firewalls (rules, apply / remove), floating IPs, primary IPs, and load balancers (services, targets, algorithm, type, networks, public interface).
- **Access:** SSH keys (including "Upload a vault key", which sends only the public half) and certificates (uploaded or managed).
- **DNS:** zones and records, including zone-file import and export.
- **Reference:** locations, server types, load balancer types, ISOs and pricing.

**How it behaves:**
- **Changes are followed to the end:** the screen reports done only when Hetzner reports the action finished, and shows its progress.
- **Rate limits** (3600 requests per hour per project) are waited out using Hetzner's reset time.
- **Read-only tokens:** a token you mark as read-only is never sent with a change.
- **Errors** are explained in one sentence: wrong token, read-only token, invalid input with the field, protected, locked, limit reached.
- **Not included:** the web console (VNC), metrics, and Hetzner's separate Robot (dedicated servers) and Storage Box APIs.

### VMware vCenter (Infrastructure)
**＋ Add ▾ → VMware vCenter** needs vCenter 7.0 or later and a vault credential.

**What you can do:**
- See VMs, hosts, clusters, datastores and networks.
- Power VMs on, shut down or restart the guest OS (through VMware Tools), suspend, power off, and reset.
- Clone a VM (vCenter 7.0 U2 or later).

**How it behaves:**
- Every change is checked by reading the VM back.
- Self-signed certificates are trusted on first use, after you compare the fingerprint.
- The password is sent once to sign in; after that only the session is used.
- **Not included:** snapshots, templates, new VMs from scratch and vMotion. Use the vSphere Client for those.

### Hyper-V (Infrastructure)
**＋ Add ▾ → Hyper-V host** works on this PC, or on a host over WinRM with your Windows sign-in or a vault credential.

**What you can do:**
- **See:** VMs, virtual switches, storage paths and checkpoints.
- **VMs:** start, shut down, save, pause, resume, turn off, reset.
- **Checkpoints:** create, apply, delete.
- **Host:** export a VM, create a new VM, import a VM.

**How it behaves:**
- It needs the Hyper-V PowerShell module on this PC.
- The app never switches on insecure WinRM settings.
- Every value reaches PowerShell as data, never as code.

### AI Engineer: run commands in a terminal you choose
- **Choosing a target:** pick a live terminal under **TARGET TERMINAL**. Commands in the AI's answers then get a **▶ Review & run** button.
- **The review** shows:
  - the exact text;
  - the target session, user, directory and environment;
  - a risk rating: read-only, changes, sensitive or destructive.
- **Confirmation:** sensitive commands ask you to type RUN. Destructive commands, and changes on PRODUCTION, ask you to type the session's name.
- **Where it runs:** only in that session. **■ Stop** sends Ctrl+C. The exit status, working directory and output come back.
- **What the AI gets back:** the output, masked and shortened, unless you turn that off.
- **Stale targets:** if the terminal disconnects, reconnects or closes, the target must be chosen again before anything runs.
- **Works with** SSH to Linux, WSL and local PowerShell. cmd, serial and Telnet sessions are listed as not usable, with the reason.

### More AI tools (AI operator)
- **Infrastructure:** inventory and actions, with the same checks and approvals as the Infrastructure screen.
- **Cloud:** any cloud provider's resource lists.
- **Context:** what you are looking at right now (names only).
- **Terminals:** the open terminal sessions, and running commands in the chosen one.
- **Notes and incidents:** search and read them. This is off by default; turn it on in **AI permissions & safety**. Each read asks first.
- **Documents:** read a PDF's text.
- **Runbooks:** create a note from real data, after you approve it.

Answers cite notes, incidents and files. Anything read from servers, APIs, terminals or documents is passed to the AI as data. Instructions hidden in it can't change what the AI may do.

## Improvements
- **Cloud providers workspace:** one sidebar entry replaces the sections Vultr and Contabo had.
  - Each provider's screens are grouped in a tree (Compute, Storage, Network, Access, DNS, Reference, Tools), with search and your recent screens.
  - Old links still work.

## User-interface changes
- **Settings reorganised into 8 categories:** Security & privacy, Cloud providers, AI & models, Terminals & connections, Appearance & navigation, Data & backups, Integrations, Updates & about.
  - Settings shows one category at a time.
  - **Search** covers every setting (Ctrl+F; Esc clears it).
  - Every card shows what its settings apply to.
  - **Appearance & navigation** and **Terminals & connections** can each be reset to their defaults. The reset asks first and changes nothing else.
- **Moved settings:**
  - screenshots folder and crash recovery: now in Data & backups → Screenshots & recovery;

  - "let the AI read without asking": now in AI permissions & safety.
- **A clean start:** the sidebar sections, the Hosts folder tree and the Cloud providers tree open collapsed. What you expand stays expanded while the app runs. To keep the sidebar as you left it, tick **Remember which sidebar sections I expanded** (Navigation & explorers).

## Security changes
- **Hetzner tokens:** stored only in the encrypted settings. They never appear in messages, logs or the audit log.
- **vCenter:** the password is sent once to sign in; after that only the session is used. The session is ended when you're done.
- **Hyper-V:**
  - Values reach PowerShell as JSON on standard input; no script is built from input.
  - A password goes only on standard input.
  - Insecure WinRM settings are never enabled.
- **Terminal commands from the AI:**
  - every run starts from your click;
  - commands are risk-rated, and the confirmation gets stricter with the risk;
  - they go only to the session you chose;
  - they are audited without the output.
- **AI data rules:**
  - AI tools enforce permissions in code, not in the prompt.
  - Notes and incidents are off for the AI by default.
  - Untrusted data is fenced, masked and bounded.

## Migration
- **Sidebar:** saved layout entries for the removed VULTR and CONTABO sections are dropped. The old "collapsed sections" list is retired, because sections now start collapsed.
- **Settings:** the old "collapsed cards" list is retired.
- Nothing else changes in your settings. Accounts, hosts, credentials and data are untouched.

## Known limitations
- Hetzner, vCenter and remote Hyper-V are tested against faithful fakes, not yet against real accounts or hosts.
- **Hetzner:** the API can't tell whether a token can write; the first change shows it.
- **vCenter:** vCenter can't report what an account may do; a refused change is reported with vCenter's reason.
- **Terminal bridge:**
  - an interrupted command reports "exit status unknown";
  - typing in the same terminal while an AI command runs mixes the output;
  - interactive programs (vim, top) wait for input, and the review flags them.
- **Not code-signed:** SmartScreen shows "unknown publisher", and in-app updates stay switched off.
