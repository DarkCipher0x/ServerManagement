# DarkCipher ServerManagement 0.2.0 (2026-10-20)

The 0.2.0 release: AI that can be switched off entirely and locked, Microsoft Azure and Google Cloud, and the app
rebuilt as separate projects with guards that keep it that way. It upgrades 0.1.20 and every 0.2.0 preview. Since
0.1.20 the changes were tried as four previews; this note gathers them (the preview notes have the detail).

## New

### AI features: on or off, and a lock (preview.1)
- **Settings → Security & privacy → AI features.** Off means no AI at all: no AI screens, sidebar items, "✦ … with AI"
  menu items, AI settings or help articles, no background AI work, model downloads or engine connections. The AI part
  of the app is not loaded. Offline features (log digests, health and fleet reports, help search) keep working, and
  your AI settings and chats stay in the encrypted store for when you turn it back on. Changes apply after a restart.
- **New installs start with AI off**; upgrades keep AI on if you were using it.
- **The lock:** a password (12+ characters) needed to turn AI on or off, allow internet AI providers, or change the
  lock. Wrong passwords wait 30 s, doubling to 10 min; every attempt is audited, never the text. No recovery by design
  (deleting `ai-lock.dcx` with the app closed removes it, and that is audited at the next start).
- **Administrators:** machine policy `HKLM\SOFTWARE\Policies\DarkCipher Systems\ServerManagement` DWORD `AiFeatures`
  (0 / 1), the MSI property `AIFEATURES=0`, and `DCX_AI_FEATURES` for one run (ignored while locked).

### Microsoft Azure and Google Cloud (preview.4)
- **Azure:** an Entra app registration signing in with a certificate (no client secrets). Virtual machines (start,
  stop = deallocate, power off, restart, redeploy, resize, instance view), AKS, App Service, Azure SQL, disks and
  snapshots, storage accounts, virtual networks, network security groups and rules, public IPs, load balancers, DNS,
  key vault settings, resource groups, every resource, and a read-only API explorer.
- **Google Cloud:** a service account's JSON key. VM instances in every zone (start, stop, reset, suspend / resume,
  machine type, serial output), images, disks and snapshots, GKE, Cloud Run, Cloud SQL, buckets, VPC networks, subnets,
  firewall rules, addresses, load balancer front ends, Cloud DNS, regions, and a read-only API explorer.
- **Both are read-only until you allow changes** for each subscription or project, and every change still asks. Keys,
  secrets, connection strings and object contents are never read. Settings → Cloud providers has a card for each.

### Interface (preview.2, preview.3)
- A **TEAM** sidebar section while a shared library add-on is enabled (Shared library, Team hosts, Team credentials
  with a "Shared only" filter).
- The **Cloud providers tree**: pin screens to a ★ Pinned branch (the "recent" buttons are gone), right-click menus that
  act on what you clicked, switch account from a provider, Ctrl+Enter / middle click for a new tab, arrow keys that
  don't load every screen.
- Tabs keep their order, search boxes say what they search, visible keyboard focus, wrapping labels, one toolbar on
  Hosts, grouped power actions, tiles that fill the width, sidebar headers with glyphs.

## Security
- A snapshot restore, a backup's "replace everything", and **start-up recovery of a damaged settings file** can no
  longer undo the AI features lock: restored settings keep the guarded values, and a recovered settings file comes back
  with AI and internet AI providers off while locked (new in 0.2.0, after preview.4). A source check stops any future
  code that writes the settings file without these guards.
- The error log masks secrets before writing.
- .NET security analyzers on every build; locked package restore with NuGet audit.
- **A software bill of materials** (CycloneDX) ships with every release: `DarkCipherServerManagement-0.2.0-sbom.cdx.json`.

## Under the hood
- The app is now **ten projects** with references pointing one way only, checked on every build; the biggest source
  files are split up; each project has a README. With AI off, the AI part of the app is never loaded (start-up about
  0.74 s and 95 MB on the test PC, against 0.76 s / 108 MB before).
- Every build runs the full self-test with AI on, the AI-off suite, and the AI-off suite again against the published
  exe, then checks start-up time, memory and file sizes against budgets.
- The add-on API, the store format, data folders and the installer's upgrade code are unchanged.

## Not tested on real accounts yet
Azure and Google Cloud were tested against simulated sign-in and API servers only, like most provider features
(see the guide's Known limitations).

## Known gaps
- No serial console on Azure or Google Cloud; Azure VM rows show no IP address (SSH and "add to hosts" ask for it).
- Planned for 0.2.0 and left out: Windows management over WinRM / CIM, mail server utilities and a built-in MaskedMail
  (later releases or add-ons; MaskedMail stays a separate app).
- Updates stay off until the releases are code-signed.
