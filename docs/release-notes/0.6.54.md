# ServerManagement 0.6.54 (2026-11-13) – DarkCipher Systems

**Public beta.** Built by an IT engineer, for engineers. Free and open source (MIT). Post-quantum ready.

## Beta: please read
- **This is a beta.** Expect rough edges, and keep backups of anything important (Settings → Data & backups).
- **The installer and the app aren't code-signed yet.** Windows SmartScreen may say "Windows protected your PC": choose
  **More info → Run anyway** only if the SHA-256 of your download matches the one published with the release. The
  update information inside the app *is* signed, twice (ECDSA P-256 and post-quantum ML-DSA-65), and the app refuses an
  update unless both signatures match.
- **Testers are very welcome**, especially for CipherChat calls and live session sharing against your own CipherChat
  server, and Windows management against remote computers.
- **Bugs and feature requests:** please use the forms on darkciphersystems.com (Report a bug, and Feature requests →
  ServerManagement).

## BREAKING: DCX-CTL portals speak dcx-ctl/2
- **Infrastructure → DCX-CTL now uses dcx-ctl/2, and only dcx-ctl/2.** The handshake is a hybrid key agreement:
  X25519 together with post-quantum ML-KEM-768 (FIPS 203), salted with the pre-shared handshake key, so a recorded
  session stays private unless both are broken. Requests and replies stay authenticated end to end (ChaCha20-Poly1305,
  per-message MACs), and the one-use handshake secrets are wiped after use.
- **Version 1 is refused.** The app no longer speaks dcx-ctl/1: a portal that answers with a version 1 reply, or that
  doesn't confirm version 2 when the session opens, is refused with a message saying so. Portals have refused version 1
  since 2026-11-10.
- **The portal server needs OpenSSL 3.5 or newer** (for ML-KEM-768). Update the portal server before you update the app.
- **Existing enrolment strings stay valid.** The key derivation for the enrolment key didn't change, so a portal you
  already added keeps working without enrolling again.
- The SSH channel to the portal is now opened like `ssh -T`: a shell request with no terminal and no command of its
  own, so the server's forced relay command runs.

## Fixed
- **Ctrl+Shift+V pasted twice in the terminal.** The shortcut asked for a paste from its key press and again from the
  browser's own paste event, so the text arrived twice. It now pastes once: holding the keys down pastes once too, and
  a second paste request within a quarter of a second is dropped. The multi-line and risky-paste confirmation therefore
  appears once, not twice.
