# ServerManagement 0.6.1 (2026-10-21) – DarkCipher Systems

Updates from the GitHub releases, signed with the DarkCipher release key; the host pane pins the way SecureCRT's Session
Manager does; the setup program really installs Nmap; and the name on screen is just ServerManagement, like the logo.

## Added
- **Updates from GitHub.** Settings → Updates → **Check for updates** now looks at the latest release on GitHub
  (github.com/DarkCipher0x/ServerManagement) by default, or at an https address of your own ("Updates from"). A new
  version shows its release notes and package; **Download and verify**, then **Install** (backup first). If you installed
  with the setup program, the update uses the new setup program; otherwise the MSI.
- **Automatic checks, your choice.** "Check automatically" (off by default), **once a day or once a week**, and
  optionally **download and verify it in the background** so it's ready in Settings → Updates. Installing always asks.
  Each is a Group Policy (`UpdateSource`, `AutoCheckUpdates`, `UpdateCheckInterval`, `AutoDownloadUpdates`).
- Until a release is published on GitHub (the repository is still private and publishing is off), a check simply says
  no release is published yet.

## Changed
- **The host pane pins straight from the Hosts page's own folder pane.** The 📌 now sits on the folder pane on the left
  of the Hosts page (no longer at the top right). One click pops that pane out beside your sessions at the left edge of
  the window, slim (about SecureCRT's width) and resizable. While it is out, the Hosts page doesn't show it twice, and
  picking a folder in the pane still filters the page. Settings that saved 0.6.0's half-screen width open at the new
  width.
- **Pin or auto-hide, like SecureCRT.** The pane's controls are on its left: 📌 (pinned: stays open when you connect)
  switches to 📍 auto-hide, which folds it to a narrow "Hosts" strip. Point at the strip and the pane slides out *over*
  your sessions (terminals aren't resized); move off it, open a session or click into a session and it slides back.
  ✕ puts it back into the Hosts page.
- **The name on screen is ServerManagement**, like the logo: the installer and setup program, Add/Remove Programs, the
  Start menu and desktop shortcuts, window titles and the Windows sign-in prompt. The publisher stays DarkCipher Systems.

## Fixed
- **Nmap is installed by the setup program.** It never was before: winget's Nmap package is stuck at 7.80 (2019), Nmap's
  free installer and its Npcap can't install silently, and the old step ran without administrator rights and ignored
  the failure. The setup program now downloads the current Nmap (7.992) from nmap.org, checks it against the SHA-512
  Nmap publishes, and opens Nmap's own setup (with Npcap) to finish, under the setup's one administrator approval. A
  cancelled or offline Nmap never undoes the ServerManagement install, and uninstalling ServerManagement leaves Nmap.
  Already installed: the switch shows **Installed** and nothing is downloaded.
- The MSI no longer tries to install Nmap (its silent winget step could never work); it says to tick it in the setup
  program or install it from nmap.org. `INSTALLNMAP` is still accepted and does nothing.

## Security
- **Updates are trusted by signature, not by server.** Each release's update information is signed with the DarkCipher
  release key (ECDSA P-256), whose private half never leaves the maintainer's Windows key store; the app has the public
  key built in and refuses anything that doesn't verify, so neither GitHub nor a hijacked account can push an update.
  The signed information fixes the version (newer only, no replay of an old release), the file names and each package's
  size and SHA-256; an MSI must also be this product at that version. Downloads come only from github.com and GitHub's
  download host (no other redirect is followed), go to the app's private temp folder, and are checked again just before
  the installer starts. Requests send no identifiers.
- The Nmap download is pinned by size and SHA-512 to the official release; anything else is refused before it runs. It
  comes only from nmap.org over https, only when you tick Nmap and it isn't installed, and never in `/quiet`.
- No change to storage or encryption.
