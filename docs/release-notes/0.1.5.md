# DarkCipher ServerManagement 0.1.5 (2026-10-18)

## Fixed: the NPU engine works with the current Foundry Local
- **The problem:** newer Foundry Local renamed `foundry service …` to `foundry server …`. The app still asked `foundry service status`, so it reported "Unknown command: 'service'" and never found the service. The "foundry service start" button failed the same way.
- **Now:**
  - The app asks `foundry server status`. If an older Foundry Local doesn't know `server`, it falls back to `foundry service status`.
  - The button is now **foundry server start** and runs `foundry server start --idle-timeout 0`, so the service doesn't stop when idle (older versions get `foundry service start`).
  - Error messages give the right command for your version.
- **Model names:** the server wants a full model ID, while Settings holds an alias such as `phi-4-mini`. The app now resolves the alias to the server's NPU build (else GPU, else CPU) before each request. A full ID is used exactly as typed, and "Load models" lists the IDs the server has.
- **A fixed address still works:** run `foundry server start --port 39839 --idle-timeout 0` and type `http://127.0.0.1:39839` into Settings → AI engine → FOUNDRY LOCAL ADDRESS. A typed address skips the CLI.

## New: a lightweight CPU model
- **Lightweight CPU model** (Settings → AI engine, with the NPU engine selected) sets and loads `qwen2.5-0.5b-instruct-generic-cpu`.
  - It needs about 1 GB of RAM, runs only on the CPU and leaves the NPU and GPU free.
  - It can still call tools; its answers are simpler than phi-4-mini's.
  - The first load downloads it.

## Changed: the AI engine defaults to Foundry Local, never Ollama
- **On a new install** the app checks the hardware once:
  - with an NPU it uses Foundry Local with phi-4-mini (Foundry runs the NPU build);
  - without one, it uses Foundry Local with the lightweight CPU model.
- **Existing settings:** if you never changed the AI engine (it was still the old Ollama · GPU default with its default model and address), it moves to the same choice. An engine you set yourself is left alone.
- **Engine list:** "Foundry Local · NPU or CPU (default)" is now first. "Detect hardware" recommends the lightweight CPU model instead of Ollama CPU-only when there's no usable GPU or NPU; Ollama is still recommended for a strong graphics card, but only when you apply it.

## Fixed: Infrastructure "＋ Add ▾" did nothing
- Clicking it opened an empty menu, so no Docker, Proxmox or Unraid provider could be added. It now opens the four choices; right-click still works.
- The same fault hit the host chips on notes and incidents (Terminal / Notes / Unlink); fixed too.

## Packaging
- Each release now has its own folder (`dist\0.1.5\`): installer, portable zip, guide, checksums, `update.json` and a copy of these notes. Earlier releases were moved into `dist\0.1.0\` … `dist\0.1.4\`.

## Also
- **Intel NPUs:** Settings and help now say that Intel AI Boost needs the Intel NPU driver for Windows before Foundry Local can use it.
- **Local commands no longer wait for a background process they start.** Before, a command that launched a service could keep the app waiting until that service stopped.

## Before you rely on it
- **Verified by the automated self-test** (180 checks, no failures, watched run, no window): a fake `foundry` CLI (both the new and the old command sets) against a real local test server, the default choice, and the "＋ Add ▾" menu on a left click. **Not yet tried on a real Foundry Local install** or NPU.
- **Not code-signed:** SmartScreen shows "unknown publisher", and in-app updates stay switched off.
