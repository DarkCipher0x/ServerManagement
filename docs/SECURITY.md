# Security model

**Target:** secure by default, privacy-preserving, defence in depth, locally controlled, with a small attack surface.
That is a goal, not a guarantee: no claim of being "unhackable" is made. Each control below has an implementation and,
where noted, a self-test.

## Assets
- Credentials (passwords, private keys, passphrases)
- API tokens and keys (Vultr, Contabo, Hetzner, AI providers), the Azure app registration's certificate (.pfx) and the
  Google service-account key; the log sinks' API keys / passwords / tokens and the Grafana token (0.4.0); the scheduled
  backup password, Teams webhook addresses and Graph refresh token, the Pingdom token, the BeyondTrust API secret and
  Password Safe key, and Password Safe passwords checked out for a session (in memory only) (0.5.0)
- Host inventory, notes and snippets
- The audit log, terminal output and screenshots
- AI conversations

## Threat actors
| Actor | Considered? |
|---|---|
| Someone with a copy of the disk or a backup | Yes |
| Another local user | Yes |
| A malicious or compromised remote server (hostile terminal output, file names, API responses) | Yes |
| Prompt injection via content sent to AI | Yes |
| Network observers | Yes |
| Malware running as the same Windows user | **Out of scope**: it can read memory and keystrokes. MFA and the app lock don't stop it. |

## Trust boundaries and controls
| Boundary | Control | Tested |
|---|---|---|
| Disk | AES-256-GCM for every store file, per-file AAD (no swapping files); key wrapped by DPAPI and/or PBKDF2 master password; since 0.6.12 Windows Hello wraps it as a post-quantum hybrid (signature + DPAPI secret), and SSH, the shared library and updates use ML-KEM / ML-DSA hybrids (ADR-090, security report §4c); atomic writes; error logs sealed once unlocked | self-test |
| Snapshots & recovery (ADR-009) | Snapshots are sealed with the data key (AAD `snapshot`), hashes checked on read; never written on low disk, pruned only after a newer one verified; restore = verified safety snapshot + journaled commit + frozen store; keyring never replaced, audit never rolled back; damaged files renamed aside, never deleted; journal names validated (no path traversal); newer data formats are not opened | self-test |
| App access | Master password, Windows Hello (0.3.0), TOTP 2FA + recovery codes (no vendor recovery or backdoor), auto-lock, lock on Windows lock/sleep, sandbox mode (kept consistent with the actual key protection) | self-test (sandbox) |
| Synced folders | Detection (OneDrive/Dropbox/Google Drive/… registry, Cloud Files attributes, junctions, UNC); dismissible warning; destination checks for exports | self-test |
| Remote output → terminal | xterm.js in an isolated WebView2 page served from memory; no navigation away, no pop-ups, no script dialogs; OSC 8 links only via an explicit confirm showing the URL (http/https only, opened in the system browser); no clipboard-write (OSC 52) handler; CSI numbers above 9999 clamped at the host bridge (a server can't freeze the tab with `ESC[99999999L`, s23) | code review (s7); fuzzed through the real page (s23) |
| Notes | One AES-256-GCM file per note (file name as AAD, so notes can't be swapped); atomic writes; revisions inside the note; Trash is a flag, only "Empty trash" deletes (with confirmation); unreadable files are never overwritten; the search index exists only in memory; backup import validates note ids (no path traversal) | self-test |
| Environment labels (ADR-017) | PRODUCTION hosts: disruptive actions (power, firewall, services, AI operator approvals, remote deletes, sync, multi-host runs) need the host's name typed, regardless of the confirmations setting; multi-line paste always previewed; removing the label asks; changes audited; label always printed (not colour-only) | self-test (recorded confirmations, live tab/strip updates) |
| Cloud providers / Contabo (ADR-020) | Provider credentials only in the encrypted settings (Contabo: client id/secret + API user/password; masked in lists, never re-shown, never in backups unless the encrypted full backup); OAuth2 tokens in memory only, per account, dropped when credentials change; no secret, token or Authorization header in errors, the error log or the audit log; sign-in errors are translated from the error code (the server's own text is not echoed); every request has a finite timeout; only safe requests are retried (reads; 429 for idempotent changes); orders are never re-sent and a timed-out change is reported as uncertain; paths built only from escaped values on fixed base URLs (no SSRF); offline mode gates both api.contabo.com and auth.contabo.com; billed or destructive actions ask (PRODUCTION hosts: type the name); one provider failing stays in its own screen/card | self-test against an in-process fake API (sign-in, failures, retries, timeouts, leaks, offline, persistence) |
| Foundry Local hands-off set-up (ADR-026) | Runs only Microsoft's own tools: `winget install --id Microsoft.FoundryLocal -e` (exact id, winget source) and the `foundry` CLI with fixed arguments (model ids come from Foundry's own catalogue, passed as one argument, no shell). It ends a process only when it is the PID Foundry reported AND named `foundrylocald`. Nothing of the user's is uploaded; offline mode blocks install and downloads; automatic big downloads wait for mains power; on by default but one switch turns all of it off; installs, downloads and repairs are audited; errors are shown, never swallowed. The self-test never runs winget, the real CLI or kills anything | self-test (fakes for CLI, winget, probe, process end; audit entries; offline/battery gates) |
| Crash recovery (ADR-022) | Unsaved remote-file text and unfinished transfers kept only in `recovery.dcx` (AES-256-GCM, file name as AAD), written on change (debounced) and on fatal error / session end / exit, deleted when empty; size-capped; never written while the store is locked. Recovery never connects, never writes to a server and never starts a transfer unless ticked; recovered tabs are disconnected; a recovered draft asks before overwriting a file that changed since; a sync's deletions are never repeated; only saved hosts are journaled (ad-hoc ones can't be found again); the choice is audited | self-test (no plaintext on disk, a real killed process recovered, recorded confirmations) |
| Single instance + renderer recovery (ADR-021) | One process per data store (a per-user `Local\` named mutex keyed by a hash of the store path — no path in the name), taken before the store, any window or browser is opened, so two processes never write the same encrypted files; a second launch only signals an activation event (no data crosses) and exits; an abandoned mutex (crash) counts as free. Each store has its own WebView2 profile, so a scratch/test store never shares a browser process, cache or cookies with the installation. A crashed terminal renderer is replaced without touching the SSH/local/serial transport (no re-authentication, no credential reuse); the replay buffer is in memory only and bounded (512K chars); recoveries capped at 3 per 10 min | self-test (real second process per store, abandoned holder, profile path; the real renderer process killed, replay, session still connected, cap) |
| Terminal features (ADR-019) | Session logs encrypted per chunk (AES-GCM, file name as context), no host name in file names, plaintext only by an explicit warned export; broadcast input asks first (PRODUCTION typed), visible strip on every member, data-level so the paste guard still applies; Telnet off by default, enabling it asks, never auto-types credentials, offline gate applies, unknown options refused, IAC escaped, sessions audited; key mappings can't capture plain typing | self-test (log at rest, loopback Telnet device, recorded confirmations, real shells) |
| Engineering dashboard (ADR-018) | No silent polling: local facts come from in-app events; remote sources (Vultr, AI engine, infrastructure) are contacted only by the visible check rule (manual / on open / interval while on screen), per-source opt-in with providers excluded by default; offline-refused sources are skipped, not attempted; the rule is listed in the Privacy view; infrastructure state kept in memory only | self-test (contact log per rule, offline skip without a blocked attempt, interval timer only while visible, Privacy row) |
| Offline / air-gapped mode (ADR-016) | One rule checked before any connection opens (HTTP clients through a guarded handler: request-URI check + a connect callback that connects only to the addresses it checked, so there is no DNS-rebinding gap and no auto-redirects; SSH also connects to the checked address; RDP, mstsc, the external terminal, web windows (each navigation and sub-request) and browser links before launch; add-ons refused unless allowed). Fails closed on resolution errors; /0 approvals refused; every block audited. Not covered: OS/WebView2 runtime services, server-side traffic, external programs after launch | self-test (fake resolver, loopback HTTP, rebinding, real clients, no socket for blocked calls) |
| File transfer (ADR-014) | Part files + atomic replace (no half file under the real name); SHA-256 verify before replace; stale resume prefixes detected; sync deletions opt-in, previewed, count-confirmed, run after copies (Recycle Bin locally); SCP paths shell-quoted (ShellQuote transformation and RemoteExec.Quote), SCP temp files in the app's private folder deleted on close; transfer history encrypted | self-test (fault injection, local sync) |
| Embedded RDP (ADR-013) | Windows' own RDP ActiveX (no third-party RDP stack); password only via IMsTscNonScriptable in memory (no file, command line or credential store); CredSSP/NLA on, server authentication level 2 (Windows prompt); bitmap cache on disk off; drives/printers/smart cards/ports/POS/microphone off by default, camera never; RDP is not broadcastable (pixels can't be redacted); WinForms error dialogs suppressed (errors reach the app's handler) | self-test (real control, refused connection, pop-out) |
| Add-on bridge and sandbox (ADR-035) | API 2 only: every message is AES-256-GCM (ephemeral ECDH P-256 per run, HKDF, counter nonce; any bad frame ends the run). Since 0.1.18 every package must declare API 2 to install, data-only ones too (ADR-036); installed API 1 program add-ons are blocked when run. Only the three pipe ends are inherited (handle list). The add-on's process and thread DACL lets nobody but SYSTEM read or write its memory, duplicate its handles or inject threads. Data-only add-ons are sealed at rest under the store key and verified on every read. | self-test (real Low-IL PowerShell over the encrypted bridge) |
| Add-ons (ADR-012) | Out of process only, started per command; Low-integrity token + Job object (kill-on-close, 512 MB, ≤ 8 processes), whitelisted environment, no unsandboxed fallback; stdin/stdout bridge with per-method permission checks; credentials only via a per-request user dialog (never cached, audited); files only user-picked; terminal text redacted; timeouts, 1 MB / 2,000-message / 256 KB-line caps; package zip-slip/size/manifest validation; per-file SHA-256 verified before every run (tamper → disabled); approval screen; updates can't add permissions without approval; no downgrades. Limitation stated in the UI: Low IL can still read files and use the network | self-test (real sandboxed PowerShell add-on) |
| Add-on full-control API (ADR-036, 0.1.18) | Only over the encrypted API 2 bridge. `app.call` runs app capabilities through the AI operator's own code path with the same checks: reads need `app.read`, private reads (notes, incidents, documents) need `app.private` and ask each time, every change needs `app.control` (HIGH) AND the user's approval of the exact action, with the add-on named and PRODUCTION needing the name typed. Host changes (`hosts.write`) are validated as a dry run and shown field by field before anything changes. Every call is audited as `addon:<id>`; a decline is error -32003. No settings or security-setting capability exists | self-test (probe add-on: capabilities listed, read with app.read, change refused without app.control and declined at the approval with it, host add/update/remove approved, unknown screen refused, calls audited) |
| Local API (ADR-011) | Off by default; raw TcpListener on 127.0.0.1 only (no remote option); Host header must be the listener (DNS rebinding); Origin → refused; Bearer capability tokens (shown once, SHA-256 stored, scoped, expiring, revocable, constant-time compare); 8 KB headers / 64 KB bodies / no chunked / 5 s; 10 rps per token; 20 failures/min → 60 s lockout; 423 while locked; no access to credentials, keys, settings, terminals or files; writes audited | self-test (real loopback HTTP + raw sockets) |
| OBS broadcast (ADR-011) | Explicit per-source start; unguessable per-broadcast URL; expiry; stop on Stop/Stop all/tab close/lock/exit; visible red indicator; text only, redacted before leaving the view (secrets, private keys incl. partial, key-like strings, optional IPs/e-mail/custom regex with timeout); password prompts freeze + hide; strict CSP page; own-origin only; 10 fps cap; incident card shows titles only | self-test |
| Incidents (ADR-010) | One AES-256-GCM file per incident and per attachment (file name as AAD); attachments bound to their incident id; screenshots captured into an incident never touch disk as PNG; AI summaries go through the "data being sent" preview (masking, destination class) with attachments named only; ids validated on import; trash flag + explicit purge; exports/saved attachments are confirmed, labelled unencrypted and audited | self-test |
| PDFs → AI | Untrusted PDFs parsed by managed PdfPig off the UI thread with size/page/time limits; no OCR or password bypass; "data being sent" preview shows the exact masked text and destination before Send | self-test |
| Screenshots → AI | Only to a model with verified image support (refused before any request otherwise); user black-out boxes burned into pixels; downscaled; memory only; audited; internet confirmation for non-local engines | self-test |
| Infrastructure providers | Read-only by default per provider; every change confirmed with target/action/environment/consequence (typed name for PRODUCTION or data loss); success only after re-reading the object (Docker inspect, Proxmox task OK + status); container ids validated before reaching a shell/URL; Proxmox: API tokens from the vault, https only, TLS pinning (changed certificate refused), privileges read from the token; Unraid: API key from the vault, mutations only if the schema offers them, ids as GraphQL variables, http only on the LAN (warned), no array/disk/share operations; no destroy operations; audited | self-test (fake engine over a real named pipe, fake Proxmox API) |
| Updates | **Switched off while no publisher certificate is pinned** (no network contact at all). When on: user-initiated (weekly check opt-in, ⚠); manifest untrusted: newer-only, same https host, fixed file name, size + SHA-256; Authenticode via WinVerifyTrust with revocation + pinned publisher thumbprint; MSI UpgradeCode + version must match; re-verified before running; backup prompt (verified backup); post-install version confirmation; no identifiers sent | self-test (real WinVerifyTrust on signed/tampered files, fake server) |
| Remote content → documents | Document viewer: in-memory, no-store, CSP for HTML, navigation and downloads blocked | code review (s6) |
| Data → AI | Click-only; per-feature switches; secret redaction on every message; `AiContext` never includes secrets or notes; internet providers off by default (⚠ + one-time confirmation), and each action asks again for an internet provider | self-test |

| AI → actions | Operator tools: read-only tools may auto-run (setting); every change asks; local file access always asks; key/credential paths refused | self-test |

## Known gaps
Tracked in `ROADMAP.md`:
- **Shared library (ADR-033):** anyone with write access to the share can delete or roll back files (detected and flagged, not prevented); a reader holds the collection key, so the editor rule is enforced by every client rejecting unsigned-by-editor items; reads are audited by each member's own app; a rogue admin is trusted. Ownership hand-over (0.1.16) needs the owner's signed offer and the new owner's acceptance; a member key backup is only as strong as its password (≥ 12 characters, PBKDF2 600k).
- **Azure and Google Cloud (0.2.0; more screens in 0.4.0)** are tested against fakes of their sign-in endpoints and APIs
  only, not yet against a real tenant or project. Their roles and scopes are the cloud's own control; the app's read-only
  switch is a second one.
- **Log sinks and Grafana (0.4.0)** are tested against TLS fakes on 127.0.0.1 and an in-process Grafana; real
  Elasticsearch / Loki / Azure Monitor / Splunk / Graylog servers are hand tests. A sink that is reachable receives the
  masked events in clear inside TLS, as syslog does: the SIEM's own access control protects them from there on.
- **Command risk assessment (ADR-028)** is rule-based, so it can misjudge clever shell constructs. It errs towards "change", and the person approving still reads the full text.
- **The AI features lock** stops someone *using the app* from changing the AI switch. It does not stop someone with full
  access to the data folder (who could read everything the app stores anyway): deleting `ai-lock.dcx` while the app is
  closed removes the lock. That is also the only recovery for a forgotten password, by design; the app audits it at the
  next start. The machine policy is the administrator-grade control and wins over the lock.
- **Admin protection (0.3.0)** protects the settings, not the data: anyone who can read your data folder and use your Windows account can still read what the app stores (that is what the master password and Hello sign-in are for). On an administrator account UAC is a consent click unless Windows is set to ask for credentials. Not tried by hand yet: the real UAC flow and Hello.
- **Prompt injection** can still mislead the AI's advice. What it can't do is widen permissions: every action is checked in code and approved by a person.
- Plaintext pre-unlock error entries (exception text only).
- **Directory sign-in (0.3.0)** is tested against fakes (a fake Entra identity provider, a substituted Windows identity,
  a self-signed LDAP certificate); a real AD domain, LDAPS server and Entra tenant are hand tests. Offline sign-in relies
  on a local proof: someone with the store's key could extend their own grace, which changes nothing they couldn't
  already read.
- **VPN engines (0.3.0)** need administrator approval for every up / down (the official clients' design); while a tunnel
  is up its rendered configuration (with the key) sits in an ACL'd folder; there is no kill switch. A real tunnel is a
  hand test.
- **Ansible (0.3.0)**: the control node sees the vault and become passwords in its process environment for the run
  (the only way Ansible reads them without a file); a root on the control node could read them — the control node is
  trusted by definition.
- Paste/clipboard policies are global only (per-host and per-workspace policies are planned). Paste safety itself is
  done (session 9: `PasteGuard`), as is the Privacy & network view.
- Local shells (ConPTY) and serial sessions run with the user's own rights by design. Serial has not been tested on
  real hardware.
- No CI: the dependency checks (NuGet audit with a locked restore, failing on high / critical advisories) and the CycloneDX SBOM (`tools\write-sbom.ps1`, one per release in `dist\<ver>\`) run in `build.ps1` on the build PC.
- Updater (ADR-008) implemented, but no code-signing certificate exists yet. The app therefore refuses to install any
  update (by design) until signed releases and a pinned thumbprint exist.
